## 📡 네트워크 구조

- **업데이트 주기**
  - 서버와 클라이언트 모두 **30FPS 고정 업데이트**
- **통신 방식:** TCP 소켓 통신 기반

- **시간 동기화**
  - 클라이언트가 **1초 주기로 Ping 패킷 전송**
  - 서버는 수신 즉시 Pong 패킷으로 응답
  - 클라이언트는 이를 기반으로 RTT 및 서버 시간 오프셋 계산에 활용
 
- **상태 동기화**
  - **클라이언트**
    - 매 업데이트 주기마다 입력 패킷(입력 상태, Tick)을 큐에 적재
    - 별도 네트워크 스레드에서 큐에 저장된 입력 패킷을 전송

  - **서버**
    - 매 업데이트 주기마다 결과 스냅샷 패킷(오브젝트들의 상태, server tick)을 큐에 적재
    - 별도 네트워크 스레드에서 패킷 전송

## 🔁 동기화 방식

### 1. 위치 및 회전
- 서버는 authoritative 방식으로 각 클라이언트의 입력 정보(입력 상태, tick)를 받아 플레이어의 위치를 계산합니다.
- 클라이언트는 입력 기반으로 예측 이동을 수행한 뒤, 서버에서 수신한 스냅샷을 기준으로 보간하여 렌더링합니다.
- 회전은 클라이언트 입력을 즉시 반영하여, 자연스러운 조작감을 유지했습니다.

### 2. 지연 보간
- 클라이언트는 Ping-Pong 패킷을 통해 측정한 RTT(Round Trip Time) 평균과 서버-클라이언트의 시간 오프셋 평균을 기반으로 서버의 과거 상태를 추정합니다.
- 보간 시점 계산:  
  '서버 추정 시각 = 클라이언트 타임스탬프 + 서버-클라이언트 평균 오프셋 - delay'
- delay는 평균 RTT의 절반에 여윳값(80ms)를 더해 계산하며, 네트워크 지연 시에도 안정적인 보간을 수행합니다.

### 3. 입력 재적용
- 클라이언트는 프레임별 입력과 결과값을 저장합니다.
- 서버로부터 수신한 결과와 클라이언트 예측 결과 간 오차가 임계값을 초과할 경우, 서버 위치로 리셋하고 입력을 순서대로 재적용합니다.
- 임계값이 넘지 않을 경우에는 3프레임에 걸쳐 점진적으로 위치를 보정하여 튀는 현상을 방지했습니다.

### 4. 서버 재시뮬레이션
- 서버는 클라이언트의 입력 tick 기준으로 입력을 버퍼에 저장합니다.
- 지연되어 도착한 입력을 위해 일정 범위 내에서 과거 상태로 리셋하여 재시뮬레이션합니다.
- 허용 범위를 초과한 입력 tick은 폐기하여, 과도한 연산과 치트 가능성을 방지합니다.

## 🚀 미사일 동기화

### 1. 클라이언트 예측
- 미사일 발사 입력 시 클라이언트에서 즉시 미사일을 생성하여 시뮬레이션을 수행합니다.
- 발사한 미사일 번호를 입력 정보에 포함시켜 전송하며, 서버는 이를 기반으로 위치를 계산할 수 있도록 합니다.

  - 지연 (Latency): 50ms ~ 100ms
- 해당 환경에서 각 플레이어와 미사일의 위치 및 회전 동기화가 잘 이루어지고 있음을 확인하였습니다.

## 🛠️ 개선 사항

### 1. 개선 완료
- **플레이어 위치 오차 개선**  
  - ~~현재 네트워크 지연이 심해질 수록 위치 오차가 점차 누적되어 스냅 + 입력 재적용이 자주 발생 = 끊김 현상~~
  - -> 서버 연결 시 초기 기준 시간과 서버 tick을 수신하여 클라이언트가 현재 서버 tick을 예측할 수 있도록 구조 개선

- **미사일 위치 오차 개선**      
  - ~~위 플레이어 위치 오차로 인해 미사일 발사 위치가 달라, 로컬 플레이어의 미사일이 흔들려 보이는 문제 발생~~
  - -> 클라이언트에서 입력 tick과 미사일 발사 방향을 서버로 전송
  - -> 서버는 해당 tick 기준으로 미사일 생성-시뮬레이션 하여 불일치 제거

- **지연 입력 처리 개선**
  - -> 네트워크 지연으로 늦게 도착한 입력 tick에 대비하여 서버에서 **일정 범위 내의 지연 입력은 재시뮬레이션하여 적용**
  - -> 허용 범위를 초과한 입력은 폐기하여 과도한 연산 및 치트 방지

### 2. 개선 필요
- **미사일 예측 후 서버 판정 보완**
  - 조작감 유지를 위해 미사일을 클라이언트에서 즉시 예측 생성했으나, 렌더링 시 서버 판정 결과를 반영하지 않기 때문에 서버에 존재하지 않는 미사일이 클라이언트에 남는 상태 불일치가 발생할 수 있습니다.

### 3. 회고
- **로컬 조작감 VS 공정성**
  - 초기에는 서버 판정을 우선하여 모든 입력 결과를 서버가 수신했을 때 반영했습니다.
  - 그 결과, 고지연 환경에서 위치 오차는 늘어갔고, 입력 반응성 또한 저하되었습니다.
  - 조작감 개선을 위해 클라이언트 예측과 서버 입력 처리를 클라이언트가 예측한 tick으로 재시뮬레이션하여 결과를 조정했습니다.

  - 결과적으로 로컬 플레이어의 미사일 발사 입력은 즉시 화면에 반영되지만 원격 플레이어의 미사일은 네트워크 지연에 따라 늦게 식별되는 현상이 발생합니다.
  - 이는 로컬 조작감을 우선한 의도에 결과로, 입력 반응성을 희생하지 않게 허용하였습니다.
